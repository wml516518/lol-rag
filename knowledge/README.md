# knowledge/ · 示例攻略语料

这个目录是 LOL-RAG **M2 检索层**的演示语料，不是官方资料，也不参与英雄/装备事实问答的
「权威数据源」——权威数据仍然只来自 `data/lol.db`（Riot Data Dragon，16.22.1）。

## 这里的文本是什么

- 全部是**人工编写的示例攻略**，标签统一写成 `source: 示例攻略（非官方）`，方便检索结果和
  UI 上做来源提示。
- 内容是**非版本数值导向**的：只讲通用思路（对线、出装方向、团战站位、视野节奏），
  不写具体伤害、金币、胜率、补丁号，避免语料随版本过期。
- 文中出现的英雄名和装备名都经过 `data/lol.db` 校验，不用虚构名字。
- 每篇结尾都有一句「以上为示例思路，具体以游戏内数据和实战为准」。

## 怎么被读取

M2 检索层会扫描本目录下的 Markdown（`guides/*.md`），由读取组件 `src/knowledge.py` 处理：
它解析 frontmatter，把 `title` 和 `tags` 拼成「主题：…」「标签：…」两行加在正文前面，让标题和
标签也参与检索；`source` 随文档一起保留用于标注来源。随后按空行分段、段内贪心拼接，把每篇切成
约 400 字以内的文本块，再走字符 n-gram + TF-IDF 相似度检索，命中后作为参考片段喂给模型。

所以写正文时要注意：**每个自然段尽量控制在 400 字以内**（超长段会被按句号再拆），并且把标题里的
关键词在正文里自然复述一遍（例如标题写「对抗高护甲」，正文里也出现「打高护甲阵容」），检索命中率
会更好。

正文里刻意保留了自然问法和同义说法（例如「打肉」「对抗高护甲」「菜刀队」「法系爆发」
「什么时候回城」），这样用户用口语提问时，n-gram 更容易命中对应段落。新增文档时延续这个习惯。

## 新增文档规范

1. 文件放在 `knowledge/guides/`，命名用 `序号-英文短名.md`（例如 `10-jungle-path.md`）。
2. 文件头必须有 YAML frontmatter：

   ```markdown
   ---
   title: 对抗高护甲阵容的装备思路
   tags: [装备, 护甲, 阵容, 出装]
   source: 示例攻略（非官方）
   ---
   ```

   `title` 必填、中文描述性标题；`tags` 为 2~5 个中文标签；`source` 固定为
   `示例攻略（非官方）`。
3. 单篇控制在 400~900 字，口语化、像玩家自己写的笔记，不要写成百科条目。
4. 不写补丁号、具体数值、精确伤害和不存在的英雄/装备名；不确定的地方用「通常/一般」。
5. 结尾加一句「以上为示例思路，具体以游戏内数据和实战为准」。
6. 只新增内容，不动 `data/lol.db` 和 `src/` 下的代码。
